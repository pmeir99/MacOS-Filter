# MacOS Filter
Chrome image, text and site filtering for Apple Silicon Macs. The development build includes a pretrained binary OpenNSFW Core ML classifier and uses Apple Vision for person masks. In the adaptive mode a high score covers the entire image. Lower scores use the existing people mask. Adjust the score cutoff in Chrome’s Filter Settings. Calibration for personal modesty standards requires a labeled evaluation set.

The model is obtained at build time from [Core ML After Dark](https://github.com/dcandre/Core-ML-After-Dark/tree/497c388569033f5b970755a4c90a0863e72785c5), checked against its pinned Git blob, compiled, and included inside the signed app. Inference needs no remote service. Target hardware is M4 and later with 16 GB.

Download the single ZIP from [GitHub Releases](https://github.com/pmeir99/MacOS-Filter/releases/latest). Open **MacOS Filter** in Applications and use **Show Extension Folder** for the one-time Chrome setup. Click **Filter Settings** in the Chrome popup to manage image, website, text, and per-site settings. Chrome asks separately for website access. The extension registers an early image visibility rule on permitted HTTP(S) pages. Images retain their layout box while pending. Site redirects use Chrome declarative network rules. Text covers use CSS highlights within individual DOM text nodes. These are visual covers, not removal from the page source.

Coverage is experimental. Browser-internal pages, arbitrary CSS/canvas, and all rendered frames of animated media are outside the verified surface. Per-person presentation, precise skin, product categories, and seven clothing levels need additional evaluated providers. See [design](docs/PRODUCT-GUIDE.md) and [installation](docs/BUILDING.md).

## Display and offline operation

Under Filtering in Chrome’s settings page, choose immediate display with image placeholders or a loading screen for the initial visible images. After eight seconds the page opens and unfinished images retain individual placeholders. Reload existing tabs after changing this option.

**Mask people only** runs a bundled DeepLabV3 FP16 Core ML model on each supported still image. It selects the person class and keeps the other classes clear. Vision person segmentation retries a failed inference. Choose Gaussian blur or a solid mask in Chrome. A clear result keeps the original image. If a scan fails, the image stays visible with an `unscanned` diagnostic. The filter handles ordinary and responsive images, dynamic image changes, accessible open shadow roots, and single CSS backgrounds on inline-styled, classed or image-role elements. It preserves the site’s own crop, shape, and controls. Public Wikipedia and X CDN reads are an optional browser setting, disabled by default. These reads omit cookies and referrers. Google Search may re-read a public thumbnail. Inference is local.

Canvas/WebGL drawings, CSS pseudo-elements, layered background images, closed shadow roots, animation across frames and unrelated unreadable CDNs have no coverage guarantee. The release build measures silhouette errors on 128 labeled COCO images and runs screenshot comparisons for portrait, group and no-person cases in a real Chromium profile on macOS.

Inference and all model weights stay on your Mac. In **Blur images containing people** mode, a detected human body or face blurs the entire image. A successful negative detection preserves the original pixels. On Google Search, if the page cannot supply pixels, the extension can request the displayed public thumbnail from Google’s thumbnail server without cookies or a referrer. Failed scans stay covered. Websites still load their own content normally. The bundled native host processes embedded raster bytes or already-loaded image pixels. The stricter modes cover unreadable cross-origin images. Mask people only leaves unreadable images visible and reports them separately in the extension popup. Local snapshots are limited to four megapixels and eight MiB. Chrome autosaves valid edits locally and sends the active image policy with each inference request. The extension has a fixed ID. Use Software Update in the app for verified downloads and automatic relaunch. Online update checks default to off.

## Experimental visual policy

Select **Seven levels** in Chrome to compare each detected person's crop with the clothing/exposure descriptions in [the prompt bank](models/policy_labels.json). Level 1 is most explicit, level 7 most covered. At the whole-image cutoff or more severe, cover everything opaquely. At the mask cutoff or more severe, cover the matched person or their detected skin. The original OpenNSFW gate also runs in this mode. Whole-image rules win even when appearance selection is active.

**Skin mask** uses the six-class MediaPipe selfie model. Body skin and facial skin can be selected separately via Include facial skin. The model groups hands and neck with other skin. A Vision detection box localizes each crop. Crowds, occluded people and overlapping boxes can give inaccurate masks. With no person box, the worker evaluates the frame. The visual appearance selector compares crop similarity to masculine/feminine prompts; it cannot establish identity. Low-margin crops are included for either selection.

Enable product families separately for underwear/lingerie, adult products/accessories and menstrual products. These optional settings classify image content without requiring matching product text. They apply to the two experimental modes. Predictions compare visual embeddings with text descriptions; the resulting level and label are estimates. Missing model output or failure produces a full cover. A confident-looking wrong prediction can still pass.

All weights, precomputed prompt embeddings and the Apple Silicon helper ship together. Model conversion, prompt preparation and dependency downloads occur during packaging. Filtering uses local Vision, Core ML and a native Apple Silicon worker linked to the bundled ONNX Runtime library. Rendering composites a solid color or adjustable Gaussian blur using the returned alpha mask. No generative fill is used.

### Chrome controls

Click the toolbar icon to pause or resume filtering for the current hostname and its subdomains, choose a site-specific image mode, or return to the inherited mode. **Open extension** opens the full settings in a tab. Site changes save automatically. A parent-domain exclusion can be edited under **Websites & text**.
